## Required adversarial scenarios

1. User A guesses user B's profile, section, resume, version, JD, run, import, or object identifier.
2. Same user switches from workspace A to B while a request/run is in flight; old responses must not populate B's view.
3. A vendor editor reads a resume originally generated by an actor with contact access; no private fields appear in JSON, DOM, PDF text/metadata, logs, or task/MCP output.
4. Membership/grant is revoked after generation or export is queued; execution and retrieval follow current authorization and documented signed-capability expiry.
5. Two saves/generation completions race; version numbering and current pointers remain consistent.
6. AI output is malformed or contains invented facts; unsupported content never becomes an accepted resume.
7. A JD/archive includes prompt injection or hostile data; it cannot change system authority, leak secrets, or execute content.
8. An audit/storage/provider dependency fails; the system preserves the approved durability/privacy policy and offers a safe retry.

|---|---|
| P1 | Both configured sign-ins; one private personal workspace; saved/reloaded profile; migration and ownership checks |
| P2 | Basic profile-derived draft or JD-grounded generation → optional JD score → preview → reviewed section suggestion/apply; scope, retry, conflict and privacy checks |

| P4 | Approved consent/sharing model; full role matrix; cross-tenant/contact isolation; durable audit evidence |
| P5 | Reviewed archive merge; grounded gap analysis; REST/MCP authorization parity |

Provider sandbox/live checks must be distinguished from mocked tests. All release environments need appropriate secret handling, restore/migration evidence, operational visibility, and chosen retention settings. “Enterprise-grade” is a product ambition, not a completed certification.

## Evidence record template

For a completed slice, record date, feature/phase, commit or changed paths, exact command/manual scenario, environment/fixture, actual outcome, and remaining limitations in the tracker. A failure stays visible until fixed or explicitly accepted. Do not mark a phase complete based on document counts or compilation alone.
